# 施工計画書アプリ

設計図書を取り込んで、**施工計画書（0）〜（16）を項目ごとのExcelで一気に作る**Windows用アプリ。
画面はブラウザ、出力エンジンは Excel（COM）。スキル `sekou-keikakusho` と同じ仕組みを、
Claude Code を使わずに誰でも使える形にしたもの。

## ダウンロード

**[Releases](https://github.com/kyouhei4444/sekou-keikakusho-app/releases/latest) から `sekou-keikakusho-app-<版>.zip` をダウンロード**し、好きな場所に展開して
`施工計画書アプリ\施工計画書アプリ.exe` を実行してください（Python は不要）。

- **施工計画書雛形は zip に入っていません**（社内様式のため公開していません）。
  社内の `施工計画書雛形` フォルダー（`（0）〜（16）` の19ファイル）を **exe の隣にコピー**するか、
  「設定」タブで場所を指定してください。
- 社員名簿・協力会社は**見本**（山田太郎など）が入っています。「設定」タブで自社の名簿に直して保存すると、
  そのPCの `data/staff.json` `data/company.json` に保存されます（GitHub には上がりません）。
- **Excel（デスクトップ版）が入っている Windows** でしか動きません。

```
施工計画書アプリ.exe（または 起動.bat）を実行 → ブラウザが開く → 工事情報・体制を入力
  → 「4. 設計書の取り込み・照査」で見積参考資料を読む（工種・数量／機械・資材＋設計照査）
  → 「3. 各項目」で作る項目を確かめる  →  「施工計画書を作る」
```

## できること／できないこと

| | 内容 |
|---|---|
| ◎ 全自動 | 雛形のコピーと差し込み（工事名・体制・下請・搬出先・現場環境改善ほか）、氏名のドロップダウン、下請の系統線、印刷体裁、確認用PDF・画像 |
| ○ ほぼ自動 | 設計図書の種類判別、**見積参考資料からの一括読み取り**（本工事費内訳書の工種・数量＋施工単価表の機械・資材）、（1）工事概要・（1-2）工事内容の作成 |
| ○ ほぼ自動 | **（6）主要資材**。見積参考資料の**明細書をたどって**（内訳書→工種明細書→科目明細書→施工単価表）品名・規格・単位・**数量**を出す。代表機労材しかない工種だけ工種数量（※印・要確認） |
| ○ 候補を出す | **（5）主要機械**の一覧。施工単価表の「代表機労材」から拾い、それが無い資料は本文の機械名から拾う。台数は資料に出ないので手入力 |
| ○ 候補を出す | **設計照査（資料どうしの照合）**。取り込みのついでに、設計図書の食い違い・記載漏れの候補を挙げ、`設計照査結果.xlsx`（照査結果＋照査チェックリスト）を出す。下の「設計照査」参照 |
| × 作らない | （7）施工方法・（8）施工管理計画の中身、計画工程表、再生資源計画の本体 |

**「読んで判断する」部分は作りません。**（7）施工方法や（8）の管理基準は、
Claude Code のスキル（`sekou-houhou` / `sekou-keikakusho`）で作ってください。

## 必要なもの

| | |
|---|---|
| **Excel（デスクトップ版）** | 必須。`.xls` を扱えるのは Excel COM だけ。Web版・LibreOffice では動かない |
| **施工計画書雛形フォルダー** | `（0）〜（16）` の19ファイル。**GitHub の zip には入っていない**（社内様式）。exeの隣に `施工計画書雛形/` を置けば自動で使う。無ければ設定タブで指定 |
| Python 3（`起動.bat` で使う場合） | `pymupdf` `openpyxl` `xlrd` が要る。exe版なら不要 |
| 建設工事必携 | （8）を手で作るときの参照用。アプリ自体は無くても動く |

## 画面

| タブ | 内容 |
|------|------|
| 1. 工事情報 | 工事名・発注者・工期・事業名・工事概要・**出力先フォルダー** |
| 2. 体制 | 自社人員（社員名簿からドロップダウン）、監督員、委託業者、下請業者（5枠） |
| 3. 各項目 | 作る項目のチェック（**（1）（1-2）（5）（6）も並びます**。設計書を取り込むと選べるようになります）、（4）指定機械、（9）安全方針、（11）搬出先、（13）現場環境改善 |
| 4. 設計書の取り込み・照査 | フォルダーを選ぶ→種類を判別→**見積参考資料から「まとめて読み取る」**（工種・数量と機械・資材を一度に、続けて**設計照査**）。表で直せます。照査だけなら「設計照査だけ行う」 |
| 5. 出力 | 生成の実行、ログ、確認用画像。**取り込んだ明細を使う（1）（1-2）（5）（6）も一緒に出ます** |
| 設定 | 雛形・必携フォルダーの場所、**社員名簿**、協力会社 |

入力した工事は「工事を保存」で `projects/` に残り、次回は上のプルダウンから開けます。

## 出力されるもの

`出力先フォルダー` に、雛形と同じ名前で `（0）〜（16）` が出ます。
`_確認用/` には、体裁を確かめるためのPDFとPNGが入ります（印刷前に必ず目を通してください）。

設計書から作る4項目だけは、雛形のコピーではなく新規のExcelです。

| ファイル | 元になるもの |
|---|---|
| `（1）工事概要.xls` | 雛形＋内訳書の工種（まえがきシートも入る） |
| `（1-2）工事内容.xlsx` | 内訳書の明細（階層ごとのブロック。足りなければ自動で増える） |
| `（5）主要機械.xlsx` | 施工単価表の代表機労材（＋算出根拠シート） |
| `（6）主要資材.xlsx` | 明細書をたどった材料と数量（＋算出根拠シートに経路を記録） |
| `設計照査結果.xlsx` | 設計照査の指摘（照査結果）、図書間の数量比較、照査チェックリスト（現地・図面）、照査した資料 |

「工事を保存」すると、**取り込んだ明細も工事データに一緒に残ります**。
次回プルダウンから開けば、読み取り直さずに（1）（1-2）（5）（6）を作れます。

## 設計照査

設計書を取り込むと、**ついでに設計照査（資料どうしの照合）**を行います。
「まとめて読み取る」の最後に自動で走り、結果は取り込みタブの一番下に表で出ます。
「設計照査だけ行う」で照査だけをやり直すこともできます。

根拠：土木工事共通仕様書［令和7年10月］1-1-1-3「設計図書の照査」2.（p.1-5）——
受注者は施工前・施工途中に、**契約書第18条第1項第1号〜第5号**に係る設計図書の照査を行い、
該当する事実があれば監督員に資料を提出して確認を求める。

| アプリが照合すること（資料の文字どうし） | 照査区分 |
|---|---|
| 工事数量総括表・見積参考資料・公表用設計書の**内訳書の工種・数量・単位**が一致するか（同じ明細の食い違いは1件にまとめる） | 第1号 不一致 |
| 内訳書の単位と、参照先の**工種明細書の「計」の単位**が一致するか | 第1号 不一致 |
| 内訳書の数量から計算した数量と、**科目明細書の見出し数量**が一致するか（1・10・100・1000 当りの見出しは比べない） | 第1号 不一致 |
| 各資料の表紙の**工事名・工事場所**、工事情報タブの入力が一致するか | 第1号 不一致 |
| **特記仕様書の工期**と、工事情報タブの工期が一致するか（未入力なら工期を参考で表示） | 第1号 不一致 |
| 内訳書の備考にある**明細書が資料の中にあるか**（参照切れ） | 第2号 誤謬・脱漏 |
| 細別に**数量・単位の記載があるか**、数量が 0 でないか | 第2号 誤謬・脱漏 |
| **極端に小さい数量**（0.05以下。例：濁水運搬 0.01ｍ３）＝計上の趣旨を確かめる | 第3号 表示が不明確（参考） |

**できないこと**：図面の中身（寸法・配筋・図面相互の整合）と現地条件（第4号・第5号）は読みません。
`設計照査結果.xlsx` の「照査チェックリスト」シート（20項目、結果欄は ○／×／－ のドロップダウン）で人が確かめてください。
チェック項目は**照査の目安としてアプリが用意したもの**で、基準の条文ではありません。工事に合わせて足し引きしてください。

- 指摘は**「要確認」の候補**です。読み取りの誤りも混ざるので、元の資料（ページを表示）で確かめてから監督員に確認を求めてください。
  誤検出は画面の「除」で外すと、Excel にも出ません。
- 名称と規格が2行に分かれて数量が下の行に印字される様式は、記載漏れとみなしません。
- サブフォルダーに旧版・変更版の総括表があると、直下の資料を基準にして食い違いを挙げます（例：つくしの の `SitescopeR7出来形/工事数量総括表.pdf`）。
- 照査結果は「工事を保存」で工事データに残ります（「除」の印も）。
- **甲斐市など県以外の発注者**の工事は、その発注者の契約約款・仕様書で照査の扱いを確かめてください。

## 雛形を変えたとき

`data/template_map.json` のセル番地がずれます。次で実際の番地を調べて直してください。

```bash
powershell -ExecutionPolicy Bypass -File engine\inspect_book.ps1 -File "…\（3）現場組織表.xls" -Sheet "（3）現場組織表" -Colors -Cells "B7,F24"
```

`-Colors` は**塗りつぶしのあるセル**を色ごとに並べます。雛形では記入欄が色分けされているので、
どこに何を入れるかを探すのに使えます。

## 他のパソコンに配る（GitHub Releases）

### 新しい版を出す

1. `app.py` の `VERSION`（画面右上に出る版）を更新してコミット・push する
2. タグを付けて push する

   ```bash
   git tag v2026.10.05
   git push origin v2026.10.05
   ```

3. GitHub Actions（`.github/workflows/release.yml`）が Windows で exe をビルドし、
   **Releases に `sekou-keikakusho-app-v2026.10.05.zip` を載せます**（数分）。
   Actions タブの「Run workflow」で、リリースせずにビルドだけ試すこともできます（成果物は Artifacts）。

zip の中身：

```
施工計画書アプリ\
  施工計画書アプリ.exe
  engine\  data\  web\    … exe の隣に置く（中身を編集できるよう、あえて exe に埋め込んでいない）
  README.md
```

### 手元で zip を作る

```bash
pip install -r requirements.txt pyinstaller
powershell -ExecutionPolicy Bypass -File build_release.ps1 -Version v2026.10.05
# 社内配布用に雛形を同梱する場合（このzipは公開しない）
powershell -ExecutionPolicy Bypass -File build_release.ps1 -Version v2026.10.05 -Templates "…\施工計画書雛形"
```

出力は `release\sekou-keikakusho-app-<版>.zip`。

### 公開しないもの

リポジトリは公開なので、次は `.gitignore` で除外しています。**コミット前に `git status` で確かめてください。**

| 除外するもの | 理由 |
|---|---|
| `data/staff.json` `data/company.json` | 社員の氏名・電話番号、協力会社・担当者 |
| `projects/*.json` | 実際の工事データ |
| `施工計画書雛形/` | 社内様式。前工事の氏名・工種・数量が残っている |
| `settings.json` | PCごとのフォルダーの場所 |

### 使う側の注意

- 雛形フォルダーの探し方は **①exeの隣 → ②上のフォルダーへ順に遡る** の順。見つからなければ「設定」タブで指定。
- 初回起動は展開に **15〜20秒** かかります（2回目以降は数秒）。
- 署名していないexeなので、Windows の SmartScreen が出たら「詳細情報」→「実行」を選んでください。
- 設定は exe の隣の `settings.json` に入ります。**別のPCに移したとき、前のPCのパスは自動で捨てて探し直します。**
- **Excel が入っていないPCでは動きません。**

## うまくいかないとき

| 症状 | 原因と対処 |
|------|-----------|
| **「選ぶ」を押しても何も出ない** | Windows のフォルダー選択画面はブラウザの裏に回ってしまうため、**アプリの中で選ぶ画面**に変えました（版 2026-09-28c 以降）。ドライブ・上へ・フォルダー一覧から選ぶか、**上の欄にパスを直接貼り付け**られます（エクスプローラーのアドレス欄からコピー） |
| **ボタンを押しても反応がないように見える** | 大きな資料の読み取りは1分ほどかかります。押すとボタンが「読んでいます…」に変わり、**画面右上に「処理中…」**が出ます。出ていれば動いています |
| **「雛形のブロック数を超えています」** | 明細が雛形の156ブロックを超えていました。足りない分を**自動で増やす**よう直しました（版 2026-09-28 以降） |
| **（5）（6）が「作る項目」で選べない（灰色）** | 設計書の取り込みがまだです。「4. 設計書の取り込み」で見積参考資料を**まとめて読み取る**と、件数が表示されて選べるようになります（版 2026-09-28d 以降） |
| **読み取った明細が異常に多い／おかしい** | 画面の表で直せます。不要な行は「除」にチェック。**画像PDF（スキャン）は読み取れません** |
| **設計照査の指摘がおかしい** | 指摘は資料の文字の照合なので、表の読み取りが崩れると誤検出が出ます。資料・ページ欄で元の資料を確かめ、誤りなら「除」で外してください。「照合できなかった資料」は画像PDFか、内訳書ではない資料です |
| **設計照査結果.xlsx が作れない** | Excel で開いたままだと上書きできません。閉じてからやり直してください |
| **主要資材の数量** | 見積参考資料の**明細書をたどって**出しています（版 2026-09-29a 以降）。数量の根拠欄に「何単位あたりの行か」を出し、算出根拠シートには経路（第0016号工種明細書→第0004号科目明細書…）を残します。**※印**の行は代表機労材しかなく数量が出ないため、その工種の数量を入れてあります |
| **主要資材に無い材料がある** | 図面の標準数量表・数量計算書にしかない材料（水抜きパイプ・目地材・吊筋など）は資料に出ないので拾えません。標準単価・市場単価の工種も内訳が印字されないことがあります。図面と突き合わせて足してください |
| **機械・資材が拾えない** | 施工単価表の探し方を直しました（版 2026-09-28b 以降）。**全ページを対象**にし、文字間隔の違いも吸収します。代表機労材が無い様式では、本文の機械名と内訳書の明細から**候補**を出します（画面に「必ず内容を確かめてください」と出ます）。それでも0件なら、その資料に機械・材料の記載がないので別の資料を選んでください |
| 画面が真っ白 | 一度閉じて `施工計画書アプリ.exe` を起動し直してください。初回は展開に15〜20秒かかります |

画面右上に**版（更新日）**が出ます。不具合を知らせるときはこの日付を添えてください。

## 注意点

- 雛形には**前工事（R8神戸ほか）の値が残っています。** アプリは差し込む欄を全部上書き（空なら消去）
  しますが、`template_map.json` に載っていない欄は残ります。出力後に確認してください。
- 数量・工種は設計図書が根拠です。**読み取った表は必ず画面で確認してから**出力してください。
- 内訳書が**画像PDF**（スキャン）の場合は読み取れません。手入力になります。
- （6）主要資材は**見積参考資料に出てくる材料だけ**です。図面の標準数量表・数量計算書
  にしかない材料（水抜きパイプ・目地材・吊筋など）は拾えないので、あとから足してください。
- 明細書をたどる順序は次のとおり。算出根拠シートに同じ経路が残ります。

  ```
  本工事費内訳書「軽量盛土 EPS工法 222ｍ３」→ 備考「第0016号工種明細書」
    → 工種明細書 第0016号（計＝1ｍ３当り）→ 備考「第0004号科目明細書」
      → 科目明細書 第0004号（222ｍ３当り）→ 発泡スチロール D-20 189.1ｍ３ …
  ```

- 代表機労材だけの工種は数量が印字されないため、**その工種の数量**を入れています（※印）。
  例：下層路盤58ｍ２ → 再生クラッシャーラン 58ｍ２（実際は 58×0.15＝8.7ｍ³ で別途算出）。
- 機械の**台数**は単価表に出ません。画面で入力してください。
- `.ps1` は **UTF-8 BOM 付き**で保存すること。BOM無しは日本語が壊れて動きません。
